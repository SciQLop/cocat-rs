# Phase 4d — OpenAPI document and Swagger UI

The JSON API is described once, by the routers that serve it: `ws::router` splits the
`OpenApiRouter` of each module and publishes the same value at `/openapi.json`, with Swagger
UI at `/docs`. The access matrix now takes the JSON routes from that document and keeps its
source scan only for the hand-written routes (UI pages, websocket, docs).

## Task 2 — schemathesis

Schemathesis 4.33.1 in a scratch virtual environment, `--checks all`, default case count,
against a release build on `127.0.0.1:18140` with a superuser (`schemathesis@example.org`) and
one room. The session was passed with `--header "Cookie: fastapiusersauth=…"`; the second run
sent no cookie at all.

The first run reported 13 failures. Every finding was either a missing response in the
document or a deliberate Python-parity answer; no server behaviour changed.

### Findings

| Symptom | Decision | Commit |
|---|---|---|
| ST103: 404 from `POST /api/invitations/preview`, `/api/invitations/accept`, `/api/group-invitations/preview`, `/api/group-invitations/accept` | Document wrong: the server answers `{"detail":"Invitation not found"}` and the annotations stopped at 400. Added 404 with the shared `Detail` body. | `5d73cc5` |
| ST103: 415 from `POST /auth/jwt/login` without a form content type | Document wrong: axum's `Form` extractor refuses the body before the handler. Added 415 (plain body, not `Detail`). | `5d73cc5` |
| ST103: 422 from `POST /auth/jwt/login` with `username=` only | Document wrong: a form missing `password` is rejected by the extractor. Added 422. | `5d73cc5` |
| ST104/ST109: `POST /auth/jwt/logout` answers 401 with an empty body while the document promised `Detail` | Document wrong: the logout handler answers a bare status when there is no session. 401 and 403 are now documented without a body. | `5d73cc5` |
| ST201: `POST /api/groups`, `/api/rooms` and `/auth/jwt/logout` accepted with "missing `fastapiusersauth` at cookie" | Tool artifact: the session arrives through `--header Cookie`, which schemathesis cannot strip from its negative cases, so those requests were still signed in. The anonymous run never accepted them; nothing changed. | — |
| ST202: `POST /auth/reset-password` and `/auth/verify` answer 400 (`RESET_PASSWORD_BAD_TOKEN`, `VERIFY_USER_BAD_TOKEN`), and `/auth/register` 400 `REGISTER_USER_ALREADY_EXISTS` on the anonymous run | Deliberate Python parity: fastapi-users answers 400 with those codes, and `tests/api.rs` pins the exact texts. Documented instead of changing the server. | — |

The rate-limit warning is expected: the limited routes document 429, and schemathesis raised
no undocumented-status failure for them. The "Authentication failed" warning comes from the
same cookie injection. The two operations without test data are the invitation previews,
which need a live token.
