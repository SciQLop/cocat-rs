# Phase 4d — OpenAPI document and Swagger UI

The JSON API is described once, by the routers that serve it: `ws::router` splits the
`OpenApiRouter` of each module and publishes the same value at `/openapi.json`, with Swagger
UI at `/docs`. The access matrix now takes the JSON routes from that document and keeps its
source scan only for the hand-written routes (UI pages, websocket, docs).

## Task 2 — schemathesis

Schemathesis 4.33.1 in a scratch virtual environment, `--checks all`, against a release build
on `127.0.0.1:18140` with a superuser (`schemathesis@example.org`), one room it owns, one
group, a room invitation and a group invitation, all created through the CLI and the API
before the run. The session is passed with `--header "Cookie: fastapiusersauth=…"`.

### Why the authenticated run was redone

The first authenticated run ended its own session: schemathesis called `POST
/auth/jwt/logout`, `PATCH /users/me` with a generated password and `DELETE /users/{id}` with
the account's own id, so every later request was anonymous — 36 operations answered only
401/403 and `GET /api/me` returned 401 after the run. The session-ending operations are now
excluded from the main run and exercised in a small run of their own, and the id-taking
routes are seeded so they do not only answer 404.

### With the session cookie

All 26 ST201 failures are the same artifact: the cookie travels in `--header`, which
schemathesis cannot remove for its negative "missing the cookie" cases, so those requests were
still signed in. The anonymous run never accepts them. The two ST202 failures are requests
the schema cannot call invalid: `POST /auth/verify` with a token this server did not issue
(400 `VERIFY_USER_BAD_TOKEN`, Python parity) and `GET …/events?cursor=0` with a cursor this
server did not issue (422); neither validity can be expressed in the document.

### Findings

| Symptom | Decision | Commit |
|---|---|---|
| ST103: 404 from `POST /api/invitations/preview`, `/api/invitations/accept`, `/api/group-invitations/preview`, `/api/group-invitations/accept` | Document wrong: the server answers `{"detail":"Invitation not found"}` and the annotations stopped at 400. Added 404 with the shared `Detail` body. | `5d73cc5` |
| ST103: 415 from `POST /auth/jwt/login` without a form content type | Document wrong: axum's `Form` extractor refuses the body before the handler. Added 415 (plain body, not `Detail`). | `5d73cc5` |
| ST103: 422 from `POST /auth/jwt/login` with `username=` only | Document wrong: a form missing `password` is rejected by the extractor. Added 422. | `5d73cc5` |
| ST104/ST109: `POST /auth/jwt/logout` answers 401 with an empty body while the document promised `Detail` | Document wrong: the logout handler answers a bare status when there is no session. 401 and 403 are now documented without a body. | `5d73cc5` |
| ST201: routes accepted while the schema says the cookie is missing | Tool artifact: the session arrives through `--header Cookie`, which schemathesis cannot strip from its negative cases. The anonymous run never accepted them; nothing changed. | — |
| ST103: 409 from `DELETE /api/rooms/{room_id}/members/{user_id}`, `PATCH` on the same path, and `DELETE /api/groups/{group_id}/members/{user_id}` | Document wrong: the owner cannot be demoted or removed and the server says so with `{"detail": "The owner keeps the owner role"}` / `"The owner cannot leave…"`. Added 409 to the three handlers. | `0884f2a` |
| ST103: 422 from `DELETE …/invitations/{invitation_id}` (room and group) | Document wrong: an id that does not fit an `i64` is refused by the path extractor. Added 422 to both revoke handlers. | `0884f2a` |
| ST103: 400 from `POST /api/rooms` and `POST /api/groups` with a control character in the name | Document wrong: the name rule refuses control characters and whitespace-only names. Added 400, and a `pattern` that makes such names invalid in the schema too. | `0884f2a` |
| ST202: invitation creation with `{"email": ""}` | Document wrong: an empty string is not an address. Added `minLength: 1` beside the existing `format: email`. | `0884f2a` |
| ST202: `GET …/events?limit=&cursor=` | Document wrong: the page size is an integer 1–10000 and the cursor is non-empty; both were declared as plain strings. Declared the limits (and `format: date-time` for `start`/`stop`) in the query parameters. | `0884f2a` |
| ST202: invitation creation with `"max_uses": 457.0` or `"expires_in_days": 45.0` | Server wrong, by JSON Schema's own reading: `457.0` is an integer, and Python's pydantic coerces it, but serde refused it. The counts now accept a number without a fractional part (`tests/api.rs::integral_floats_are_accepted_for_invitation_counts`, red first). | `0884f2a` |
| ST202: `POST /auth/reset-password` and `/auth/verify` answer 400 (`RESET_PASSWORD_BAD_TOKEN`, `VERIFY_USER_BAD_TOKEN`), and `/auth/register` 400 `REGISTER_USER_ALREADY_EXISTS` on the anonymous run | Deliberate Python parity: fastapi-users answers 400 with those codes, and `tests/api.rs` pins the exact texts. Documented instead of changing the server. | — |

The rate-limit warning is expected: the limited routes document 429, and schemathesis raised
no undocumented-status failure for them. The operations without test data are the ones that
need an id or a token issued by the server (invitation previews, catalogue events).
