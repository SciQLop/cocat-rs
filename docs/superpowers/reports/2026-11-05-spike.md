# Spike report — cocat-rs against the go/no-go gates

Date: 2026-11-05. Branch `spike`. Raw results: `bench/results/*.json`; how to rerun:
`bench/README.md` (`SERVER=rust|python bench/run_gates.sh`, then `bench/compare.py`).

**Verdict: GO on every performance gate, no hard NO-GO line crossed. Four correctness
gates have not been run yet (below); the spike is not closed until they are.**

## Setup

- One machine: AMD Ryzen 7 5800X (8 cores, 16 threads), 62 GB RAM, Fedora 44 in a toolbox
  container. Not a quiet machine: other builds ran during some scenarios, which can only
  have made both servers look slower.
- Python: cocat 0.15 on the `rust-spike` branch of cocat-ui (pycrdt, wiredb, uvicorn).
- Rust: `cocat-server` release build at the `spike` branch head, jemalloc global allocator.
- Workload as the design states: a 100 k-event room (`bench100k`, 100 catalogues × 1 000
  events, 37.8 MB `.y` built through `cocat.DB`), 1 k-event rooms for scale-out and soak.

Notes on reading it:

- The scale-out run was close to harness-bound (the clients used 0.89 of a core), so 7.5× is
  a floor for Rust, not its ceiling.
- The negative drifts mean memory went *down*: jemalloc returns an unloaded room's pages.
- The Python RSS figure is the harness's 20 cold opens: Python never frees a loaded room.

## What the spike found and fixed

1. **glibc kept freed rooms.** With the system allocator a 100 k room left ~1 GB resident
   after it unloaded. jemalloc returns it (and keeps the open room at 567 MB).
2. **One 38 MB first sync per joining client.** 50 simultaneous joins held ~1.9 GB. The room
   now encodes the full state once per join wave and shares it.
3. **Nagle's algorithm** delayed single small frames; disabled on accepted sockets (p99 15 → 2 ms).
4. **Harness flaws**, each fixed and re-measured: a 1 MiB client frame limit; edits sent as
   state-vector diffs, which carry the whole delete set and made the file grow quadratically
   (real clients send transaction updates); the one-hour session cookie expiring inside the
   one-hour soak.

## Deviations from the plan

- The live slice is five tests at the spike; the kick, role and delete tests needed `/api`,
  which phase 2a added (25 tests now pass live).
- The spike used the Python schema and Python-compatible tokens; phase 1 owns the schema
  with sqlx migrations.
- Refusal is HTTP 403 at the handshake, not accept-then-1008 (design corrected).
- Timebox: the spike ran in one day, well inside the 10-day box.
