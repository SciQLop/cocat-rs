# Phase 1 — Rooms and lifecycle — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the spike into the phase-1 server: its own schema, the room lifecycle
(delete, role change, removal, ownership transfer) that closes the sockets it revokes,
bounded per-client queues, and a room memory budget.

**Architecture:** The spike's shape stays: one OS thread per room owning the `Doc`,
sockets talk to it through channels. Revocation goes through the room thread (it already
knows every client), so a kick is one command on the room's FIFO channel; the websocket
bridge re-reads the role *after* attaching, which closes the handshake race the same way
the Python server does. Lifecycle mutations live in one `lifecycle` module that does the
SQL change *then* the revocation, so phase 2's REST routes are thin wrappers.

**Tech Stack:** Rust 2024, axum 0.8, tokio, yrs 0.28, sqlx 0.9 (sqlite, `migrate` +
`macros` features), jemalloc (tikv-jemallocator 0.7).

**Spec:** `docs/superpowers/specs/2026-11-05-cocat-rs-design.md` (phase 1, "The HTTP and
websocket contract", "Concurrency and memory"). Behaviour reference: the Python server in
`/home/jeandet/Documents/prog/cocat-ui` (branch `rust-spike`), `src/cocat/app/{rooms.py,
actions.py,connections.py,users.py}`.

## Review Focus

1. **A role change during the handshake.** The role is read before the 403 check, then
   the owner downgrades the member before the socket attaches. Expected: the socket ends
   up with the new role or is closed 1008, never writes with the old role (Task 3 test
   `a_downgrade_between_handshake_and_attach_is_honoured`).
2. **A deleted room coming back.** Deleting a room while a client is attached, then a
   new room with the same id. Expected: the old file is gone and nothing of the old
   document reappears, even though the room thread flushes on unload (Task 3 test
   `a_deleted_room_does_not_resurrect_its_file`).
3. **A client that stops reading.** A socket that never reads while others edit.
   Expected: server memory stays bounded and that client alone is closed 1013 (Task 2
   test `a_client_that_does_not_read_is_closed_1013`).
4. **Two owners.** A transfer that fails halfway, or a CLI `set-room-owner` racing a
   transfer. Expected: exactly one owner at all times, enforced by the schema (Task 1 test
   `a_second_owner_is_rejected_by_the_schema`).
5. **Email case.** A user created as `Alice@X.org` logs in as `alice@x.org`. Expected:
   same user (fastapi-users matches emails case-insensitively), and creating
   `alice@x.org` again is refused (Task 1 test `emails_match_case_insensitively`).

### Task 2: Per-client outbox: bounded frames and a close signal

**Files:**
- Modify: `crates/cocat-server/src/room.rs`, `crates/cocat-server/src/ws.rs`
- Test: `crates/cocat-server/tests/room.rs`, `crates/cocat-server/tests/websocket.rs`

**Interfaces:**
- Produces (in `room.rs`):
  ```rust
  pub const OUTBOUND_FRAMES: usize = 1024;
  pub struct Outbox { pub frames: tokio::sync::mpsc::Sender<Bytes>, pub close: tokio::sync::oneshot::Sender<CloseReason> }
  pub struct Inbox  { pub frames: tokio::sync::mpsc::Receiver<Bytes>, pub close: tokio::sync::oneshot::Receiver<CloseReason> }
  pub fn outbox() -> (Outbox, Inbox);
  #[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum CloseReason { Revoked, TooSlow, OverBudget }
  impl CloseReason { pub fn code(self) -> u16; pub fn reason(self) -> &'static str }  // 1008, 1013, 1013
  ```
  `RoomHandle::attach(client, role, outbox: Outbox)` replaces the `UnboundedSender`.
- The room thread sends with `try_send`. `Full` → the client is removed from the room and
  `close.send(TooSlow)`; `Closed` → removed silently.
- The bridge's writer `select!`s on `inbox.close` (biased, first) and `inbox.frames`; a
  close reason sends `Close(code, reason)` at once, without draining queued frames, and
  ends the socket.

1024 frames is ~20 s of a room at 50 edits/s; the shared full-state `Bytes` counts as one
frame, so the bound is in frames, not bytes.

  server; one socket never reads, another sends `OUTBOUND_FRAMES + 50` small updates; the

### Task 3: Revocation through the room thread

**Files:**
- Modify: `crates/cocat-server/src/room.rs`, `crates/cocat-server/src/ws.rs`
- Test: `crates/cocat-server/tests/room.rs`, `crates/cocat-server/tests/websocket.rs`

**Interfaces:**
- Consumes: Task 2 `Outbox`, `CloseReason::Revoked`; Task 1 `db::role_in`, `db::set_role`.
- Produces:
  ```rust
  RoomHandle::attach(&self, client: ClientId, user: Uuid, role: Role, outbox: Outbox) -> Result<(), RoomGone>
  RoomManager::revoke(&self, room_id: &str, user: Uuid)   // async; closes that user's sockets in that room, 1008; no-op if the room is not open; returns once the room thread processed it
  RoomManager::delete(&self, room_id: &str)               // async; closes every socket 1008, unloads WITHOUT a final write, removes `<update_dir>/<room_id>.y`; works whether or not the room is open
  ```
- Bridge order: handshake role check (403 as today) → `attach` → re-read
  `db::role_in`; if it is `None` or differs from the attached role, close 1008. Python
  does the same (`users.py` `websocket_auth` docstring): any revocation either commits
  before the re-read or finds the attached client on the room's FIFO channel.
- `delete` while the room is open goes through a `RoomCommand::Delete { done }` handled
  by the room thread: it closes clients, removes itself from the registry under the
  registry lock (like `close_room`), drops the store, deletes the file, acks. When the
  room is not open, `delete` removes the file under the registry lock so a concurrent
  `get_or_open` cannot reopen it in between.

### Task 4: Lifecycle actions

**Files:**
- Create: `crates/cocat-server/src/lifecycle.rs`
- Modify: `crates/cocat-server/src/lib.rs`
- Test: `crates/cocat-server/tests/lifecycle.rs`

**Interfaces:**
- Consumes: Task 1 db mutations, Task 3 `RoomManager::revoke`/`delete`.
- Produces:
  ```rust
  #[derive(Debug, thiserror::Error)] pub enum LifecycleError { NotFound, Forbidden, Conflict(&'static str), Db(DbError) }
  pub async fn delete_room(state: &AppState, room_id: &str, actor: Uuid) -> Result<(), LifecycleError>
  pub async fn set_member_role(state: &AppState, room_id: &str, actor: Uuid, member: Uuid, role: Role) -> Result<(), LifecycleError>
  pub async fn remove_member(state: &AppState, room_id: &str, actor: Uuid, member: Uuid) -> Result<(), LifecycleError>
  pub async fn transfer_ownership(state: &AppState, room_id: &str, actor: Uuid, new_owner: Uuid) -> Result<(), LifecycleError>
  ```
  Rules, copied from Python `rooms.py`: the actor's role must be at least the minimum,
  else `NotFound` when not a member, `Forbidden` when the role is too low. Delete,
  set-role and transfer need owner; remove needs owner, or viewer when removing oneself.
  `Owner` cannot be assigned through set-role and the owner's own role cannot change
  (`Conflict("The owner keeps the owner role")`); the owner cannot be removed or leave
  (`Conflict("The owner cannot leave or be removed")`); a target that is not a member is
  `NotFound`. Each action commits the SQL change, then revokes (`revoke` for the target,
  `delete` for the room). Transfer revokes the new owner only, like Python.

### Task 5: Room memory budget

**Files:**
- Modify: `crates/cocat-server/src/room.rs`, `crates/cocat-server/src/cli.rs`,
  `crates/cocat-server/src/ws.rs`
- Test: `crates/cocat-server/tests/room.rs`, `crates/cocat-server/tests/websocket.rs`

**Interfaces:**
- Produces: `RoomManager::new(update_dir: PathBuf, budget: Option<u64>)` (bytes);
  `RoomError::OverBudget { room_id: String, needed: u64, budget: u64 }`;
  `pub const MEMORY_PER_FILE_BYTE: u64 = 16;`
- A room's estimate is its `.y` file size × `MEMORY_PER_FILE_BYTE`, taken at open
  (measured: 37.8 MB file → 566 MB resident with jemalloc). `get_or_open` refuses when the
  sum of open rooms' estimates plus the new one exceeds the budget; the estimate is
  released when the room leaves the registry (unload or delete).
- `serve` reads `COCAT_ROOM_MEMORY_BUDGET` in megabytes; unset or empty means no budget; a
  value that is not a positive integer is a startup error naming the variable.
- The bridge closes an over-budget attach with `CloseReason::OverBudget` (1013, "server
  memory budget reached") and logs room id, needed and budget.
- `// simplify:` LRU unloading of client-less rooms is skipped: in phase 1 a room with no
  client is never open. Add it when phase 2's REST reads keep rooms open.
